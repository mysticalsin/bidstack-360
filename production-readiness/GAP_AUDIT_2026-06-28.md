## 2. BLOCKERS — must close before any production launch

Both reduce to two themes: **(A) PII-at-rest is coded but never proven on a live DB**, and **(B) no real
backup exists.**

### B1 — PII-at-rest encryption is unproven on any live release DB (Gate 5, the #1 blocker)
- `scripts/encrypt-existing-pii.ts` has **never run against a real DB** — the only evidence
  (`production-readiness/evidence/2026-06-28/pii-evidence-gates.log`) is `--selftest` lines;
  `deploy-evidence/pii-ciphertext-latest.json` does not exist.
- **The trap:** `env.ts:277-281` **forces `PII_FIELD_ENCRYPTION=true` in prod**, and
  `pii-encryption.ts:248` rewrites email-equality filters to `emailHash`. Deploy without backfilling first
  → every pre-existing Contact/Lead/KamConsultant row stays **plaintext email/phone with NULL emailHash**,
  and **find-by-email silently misses them.**
- **Unblock (ops):** with release-DB access + `PII_ENCRYPTION_MASTER_KEY`, *flag still false*:
  `tsx scripts/encrypt-existing-pii.ts --dry-run` → `--apply` → flip flag → `pnpm deploy:evidence:pii` →
  commit the ciphertext artifact. **Effort M.**

### B2 — No production backup proven to exist (offsite / encrypted / immutable)
- Only a **local** `pg_dump→pg_restore` drill exists. `BACKUP_RESTORE_REPORT.md:26-31` self-declares prod
  backup schedule/encryption/retention/immutability/offsite "None verified." `grep pg_dump|cronjob` over
  `infra/ scripts/ .github/` = **0 hits**; `BACKUP_S3_BUCKET`/`BACKUP_ENCRYPT_KEY` are dead config. Azure
  bicep sets `backupRetentionDays:35` geo-redundant but `main.bicep` is an **unvalidated draft, never run.**
- **Unblock (cloud):** stand up managed-Postgres automated backups + PITR; record
  retention/region/immutability evidence. **Effort L.**

> **Release-state risk (process, not a gate):** the hardening set is **147 uncommitted files**. Webhook
