## Findings log (numbered)

### F1 — Sales Toolkits 500 · FAIL → ✅ FIXED
`/api/v1/sales-toolkits/store` 500 (`P2021 public.sales_toolkits does not exist`,
`sales-toolkits.ts:119`). Two causes, both **local-env**: (a) stale generated Prisma
client (no `salesToolkit` accessor), (b) the `20260624130000_sales_toolkit_store`
migration never applied to the dev DB (which also had history drift).
**Fix:** `pnpm db:generate` (project auto-renames the locked DLL) + `prisma db push`
(deploy blocked by `kam_consultants_org_fk` drift; push reconciled additively, no
data loss). API restarted → `/store` 200, page renders graceful empty state.
*CI/prod regenerate + migrate on build, so this never reaches a clean env.* As a
side effect it also cleared the long-standing `apps/api` typecheck errors on
`prisma.salesToolkit` (F12).

### F2 — Top Accounts / Sector / KAM empty despite €11.9M pipeline · DATA/SEED (not code)
Converged by API-Tester (QA-API-02/03), PM (PM-01), and senior-fullstack (FS-01):
the stub org `org_seed_mantu` was seeded by `pnpm db:seed`, which creates **65 opps
with `companyId = NULL` and no real `Company` rows** — only E2E/SCOPE/audit junk
companies exist. `/accounts/top` correctly runs `source:auto` (LEFT JOIN opps ON
`company_id`) → €0 for every company; the UI filters synthetic names → empty. The
real demo dataset (companies + `companyId`-linked opps + `topAccountRank`) is
produced only by `pnpm db:seed:demo` into a separate `demo_org_<stamp>`.
**Not a code bug** (fullstack confirmed and did not hack it).
**Fix (data — recommend, not auto-applied):** either repoint the stub org at a
fresh demo org (`pnpm db:seed:demo` → set `BIDSTACK_STUB_ORG_CLERK=demo_org_<stamp>`
+ restart api), or make `pnpm db:seed` demo-correct (create Company rows for the
fixture customers, set `companyId` on those opps, set `topAccountRank` on the top 3).
Also fixes Sector View sparsity and Companies junk (F11).
**Compounding (small code):** the Top-Accounts empty-state copy mis-says "add
opportunities with values" when they exist (PM-01b) — fix copy when the data lands.

### F3 — Dashboard currency mix (€11.9M vs $13.54M) · ✅ FIXED
`InsightsBar.tsx:65` hardcoded `€` and skipped the currency conversion every other
dashboard card does. **Fix (senior-fullstack):** route the pipeline pill through
`formatMoney(convert(pipelineValue,'EUR'), currency)` + updated 6 locale strings.
typecheck + lint + `OrgDashboard.test.tsx` green. (Follow-up: `TopAccountsPage`
also hardcodes EUR — route it through the currency store too.)

### F4 — `/api/v1/competitors` 400 (unusable) · ✅ FIXED
`competitors.ts:56` `findMany` had no `take` → the unbounded-query guard rejected
every call (Competitor Intelligence list never loaded). **Fix:** `take: 500`
(org-curated, low-volume). Verified `competitors=200`. typecheck + lint clean.

### F5 — Saved-view input bounds NOT enforced at runtime · Medium · ✅ FIXED
The `SavedViewFilters` caps added earlier live only in `packages/shared/src`; the API
imports the compiled `dist` (built before the edit), so 60-key / 5000-char filter
POSTs returned **201**. **Fix:** `pnpm --filter @bidstack/shared build` + restart api.
Verified: 60-keys → 400, 5000-char → 400, normal → 201.
**Process fix to enforce:** CI/CD and `pnpm dev` must build/watch `@bidstack/shared`
before `api`/`worker` (the Azure CD draft + dev should guarantee this), else other
shared-package edits also won't be live.

### F6 — Saved-view residual hardening · Low · documented
No per-user count cap on saved views; a single `filters` blob can still reach ~10 MiB
(body-limited) and is doubled into `auditLog.diff` on PATCH. View `name` not
sanitized (safe today — React escapes; no `dangerouslySetInnerHTML` path). Add a
per-user cap + total serialized-size cap; escape at any future CSV/PDF/email export.

### F7 — `/api/goals` 404, orphaned hook · minor · documented
`apps/web/src/hooks/useGoals.ts` calls `/api/goals` (no route registered); the hook
is imported by nothing → dead code. Remove or implement.

### F8 — Forecasts blank in a top-level Sales door · P1 product gap · documented
No `forecast` rows; the page computes nothing from the 65 live opps. Min: seed
forecasts; better: derive a pipeline-weighted baseline (rep-adjustable).

### F9 — Strategic doors blank on a fresh org (KAM / References / Analytics) · P2 · documented
Legit-empty-by-design but poor demo time-to-value. Seed: 1 KAM-designated account,
2–3 references, 1 default dashboard so each door is alive on first open.

### F10 — Concept duplication (IA) · P2 · documented
Two "key account" systems (`tier:key` vs `kamStatus`) and two "reference" systems
(`reference` vs `projectReference`) ship in the same nav. Recommend a product
decision to consolidate/differentiate (an `/adhd` before further KAM work).

### F11 — Dev DB is test-artifact polluted · documented (= F2 data fix)
All 8 companies are E2E/SCOPE/audit junk; pollution leaks into reports, custom
objects, territories, service cases. Clean reseed resolves F2/F11/sector together.

### F12 — Pre-existing `apps/api` typecheck `salesToolkit` errors · ✅ RESOLVED
Cleared as a side effect of the F1 client regen — `pnpm --filter @bidstack/api
typecheck` is now clean.
